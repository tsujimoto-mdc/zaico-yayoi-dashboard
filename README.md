# 社内全在庫（弥生・本社・物流）確認ダッシュボード

ZAICOのCSV・物流(潤井戸)在庫のCSV・弥生在庫表のExcelをアップロードしてボタンを1回押すだけで、

- **① 拠点別在庫一覧**（本社 / 3F / 4F / 4F(PKG不備) / 物流 / 弥生 ＋ 合計）
- **② 弥生ゼロ在庫あぶり出しリスト**（弥生在庫が0なのに4F(ZAICO)には残っている品番の一覧）

の2シート構成のExcelがダウンロードできる社内向けWebツールです。

本ツールの主目的は②のあぶり出しリストです。4F保管分のうち弥生データ側で在庫管理されていない
（棚卸・計上漏れの可能性がある）商品を洗い出し、廃棄可否判断につなげます。

既存ツール [`zaiko-all-dashboard`](../zaiko-all-dashboard) の構成・UIを踏襲し、弥生在庫と
あぶり出しリストを追加拡張したものです。

---

## 1. フォルダ構成

```
zaico-yayoi-dashboard/
├── app.py                 ← アプリ本体（画面）
├── inventory_core.py      ← 集計ロジック
├── requirements.txt       ← 必要なライブラリ一覧
├── secrets_example.toml   ← Secrets設定のひな形
├── .gitignore
└── README.md
```

テンプレートファイルは不要です。アップロードされた3つのファイルだけで集計します。

---

## 2. アップロードする3ファイル

| # | ファイル | 例 | 形式 |
|---|---|---|---|
| ① | ZAICO ダウンロードCSV | `inventory_download_YYYYMMDD_HHMMSS.csv` | CSV（UTF-8） |
| ② | 物流(潤井戸)在庫CSV | `009_物流在庫リスト_xxxxxx.csv` | CSV（Shift-JIS） |
| ③ | 弥生在庫表Excel | `弥生在庫YYYYMM.xlsx` | Excel（.xlsx、ヘッダー行なし） |

文字コードは自動判定します（UTF-8 / Shift-JIS どちらでも可）。

**必要な列**

- ① ZAICO CSV … `型番` / `保管場所` / `数量` / `物品名`
- ② 物流 CSV … `商品コード` / `商品名` / `在庫数（総ピース）`
- ③ 弥生Excel … 1シート目・ヘッダー行なし。**A列＝品番、B列＝商品名、G列＝在庫数**（位置で判定します）

---

## 3. 品番マッチングルール（弥生品番 ⇔ 正式品番）

弥生在庫表の品番表記は他の在庫表と形式が異なるため、突合時に変換します。

- 正式品番の例：`md-76181-1`
- 弥生品番の例：`76181-1(15438)`（`md-` プレフィックスが付かず、末尾に括弧付き数字が入る）
- 変換ロジック：弥生品番から末尾の `(数字)` を除去し、先頭に `md-` を付与する
  - 例：`76181-1(15438)` → `md-76181-1`
- 変換ルールが当てはまらない品番（`md-` を付けても他表と突合できない旧商品・外注品など）は
  「要確認」列にマークして出力します（あぶり出しリストの集計対象からは除外）。

---

## 4. 集計ルール

品番（ZAICO「型番」＝物流「商品コード」＝弥生品番を変換したもの）で突き合わせ、1品番1行に集計します。

| 拠点列 | 集計元 |
|---|---|
| 本社 | ZAICO CSV で保管場所が **「本社在庫」** の `数量` 合計 |
| 3F | ZAICO CSV で保管場所が **「★3F EC★」** の `数量` 合計 |
| 4F | ZAICO CSV で保管場所が **「◆4F EC◆」「□４F 他社商品□」** の `数量` 合計 |
| 4F(PKG不備) | ZAICO CSV で保管場所が **「●４F PKG不備●」** の `数量` 合計 |
| 物流 | 物流 CSV の **「在庫数（総ピース）」** 合計 |
| 弥生 | 弥生在庫表 **G列（在庫数）** の合計 |
| 合計 | 本社 ＋ 3F ＋ 4F ＋ 4F(PKG不備) ＋ 物流 ＋ 弥生 |

- 同じ品番が複数行ある場合は合算します。
- いずれかの拠点に在庫データがある品番はすべて掲載します（合計0も含む）。
- 並び順は品番の昇順（要確認品番は末尾）。
- 商品名は ZAICO「物品名」→ 物流「商品名」→ 弥生「商品名」の優先順で埋めます。
- ZAICO CSV で「型番」が空の行、上記5拠点以外の保管場所の行は集計対象外にし、
  件数を画面に警告表示します（入力ミス確認用）。

### あぶり出しリスト（シート②）の条件

- 弥生在庫表の在庫数が **0または存在しない**、かつ **4F（ZAICO）在庫が1以上** の品番
- 要確認品番（品番変換できなかった弥生専用品番）は対象外

運用ルール（保管場所名・列名など）が変わったときは、
`inventory_core.py` 冒頭の「業務ルール設定」だけ直せばOKです。

## 5. デプロイの流れ（初回のみ）

### ステップ1: GitHubリポジトリを作成する

1. GitHub（[github.com](https://github.com)）でアカウントがなければ作成
2. 「New repository」で新規リポジトリを作成
   - **在庫・商品情報を扱うため、必ず Private（非公開）を選択してください**
3. この `zaico-yayoi-dashboard/` フォルダ一式をアップロード
   （`app.py`, `inventory_core.py`, `requirements.txt`, `.gitignore`,
   `secrets_example.toml`, `README.md`）
   - `secrets_example.toml` はアップロードしてOK（値はひな形です）
   - 実際のCSV・Excel・生成後のExcelはアップロードしないでください
     （`.gitignore` で `*.csv` / `*.xlsx` を除外済みです）

### ステップ2: Streamlit Community Cloud にデプロイする

1. [share.streamlit.io](https://share.streamlit.io) にGitHubアカウントで連携
2. 「Create app」→ 作成したリポジトリ・ブランチ・`app.py`（パス:
   `zaico-yayoi-dashboard/app.py`）を選択してデプロイ

### ステップ3: 合言葉を設定する（任意）

社内限定URLだけで運用するなら不要です。合言葉を掛けたい場合のみ:

1. アプリ管理画面 → 「Settings」→「Secrets」
2. 次の1行を貼り付けて保存

```toml
APP_PASSWORD = "実際の合言葉"
```

---

## 6. 使い方

1. アプリのURLにアクセス（合言葉を設定していれば入力）
2. **① ZAICOダウンロードCSV(.csv)** をアップロード
3. **② 物流(潤井戸)在庫CSV(.csv)** をアップロード
4. **③ 弥生在庫表Excel(.xlsx)** をアップロード
5. **④「🧮 エクセル作成」** を押す
6. **⑤ ダウンロード** から `社内全在庫_弥生本社物流_YYYYMMDD_HHMM.xlsx` を保存

画面には確認用のプレビュー表（拠点別在庫一覧／あぶり出しリストの2タブ）と
サマリー（拠点別の在庫合計・品番数・要確認品番数・あぶり出し件数）も表示されます。

## 7. ローカルで動かす場合（任意）

```powershell
cd zaico-yayoi-dashboard
pip install -r requirements.txt
streamlit run app.py
```

`.streamlit/secrets.toml` に `APP_PASSWORD` を書けば、ローカルでも合言葉が有効になります
（このファイルは Git 管理対象外です）。

---

## 8. 運用・セキュリティ上の注意点

- **リポジトリは必ず Private に**（在庫・商品情報を扱うため）。
- アップロードしたファイル・生成したExcelはサーバーに保存されず、その場のメモリ上のみで
  処理されます。必要なファイルは必ずダウンロードして保存してください。
- Streamlit Community Cloud の無料枠はしばらく使われないと自動休止し、
  次回アクセス時に再起動（数十秒）が必要になる場合があります。

## 9. 困ったときは

- **「必要な列が見つかりません」と出る**
  → CSVのダウンロード設定で、上記「必要な列」が含まれているCSVか確認してください。
- **「G列（在庫数）を読み取れません」と出る**
  → 弥生Excelの列構成（ヘッダー行の有無・列の並び）が変わった可能性があります。
  `inventory_core.py` の `YAYOI_COL_IDX_SKU` / `YAYOI_COL_IDX_NAME` / `YAYOI_COL_IDX_QTY` を
  実際の列位置に合わせてください。
- **特定品番の物流在庫が0になる**
  → ZAICOの「型番」と物流の「商品コード」が完全一致しているか（表記ゆれがないか）確認してください。
- **保管場所の警告が出る**
  → ZAICO側で保管場所名が変わった、または新しい保管場所が追加された可能性があります。
  `inventory_core.py` の `ZAICO_LOCATION_MAP` を実際の名称に合わせてください。
- **要確認品番が多い**
  → 弥生品番が `品番(数字)` の形式でない場合は自動変換できません。旧商品・外注品など、
  運用側での個別確認が必要です。
